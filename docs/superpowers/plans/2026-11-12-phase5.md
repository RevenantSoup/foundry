# Phase 5 implementation plan

Goal: Stripe test Checkout with verified paid-order downloads, plus a complete authenticated remote worker bridge for Vercel. Existing local CLI, buyer authorization, pricing and legal gates remain unchanged.

Architecture: public Next.js routes dispatch payment operations to the shared Python service. Local mode invokes web/bridge.py; remote mode sends authenticated HTTPS requests to foundry.worker. Worker owns SQLite, jobs, uploads and file bytes. Stripe's official Python SDK creates test Sessions and verifies raw webhook signatures in that same trusted service; no card fields are persisted. Next streams files without exposing worker paths or credentials.

Constraints: Python 3.11; no live Stripe keys or charges; no production deployment; buyer keys remain hashed with 401/403/429; QA 0.90 and quota exit 2 unchanged; only existing licensed/synthetic demo rules. Main commit/push only after tests, web build and Docker verification.

Review focus: duplicate/out-of-order webhook events; Stripe amount/currency/metadata mismatch; key separation and backend errors leaking URLs; all file/upload/job operations working without local writable disk; serverless payload limits and streamed downloads.

- [x] Payments: failing pytest contracts, schema orders/grants, official SDK test-only configuration, idempotent pending Session creation, signed-raw-body webhooks, owner-bound status and 24h signed download grants; test tampering, mismatch, expiry and no card storage.
- [x] Worker: authenticated bounded HTTP service exposing only existing bridge modes, durable jobs, validated references and streamed assets; test 401/key separation, unknown modes, malformed uploads and local bridge regressions.
- [x] Next integration: HTTPS remote transport, explicit timeout/error mapping, local fallback, remote plan/asset/job routing, checkout/webhook/order/download endpoints, purchase and return UI. Test API routes against a fake Stripe SDK and a real loopback worker, with browser tests for both remote and local modes.
- [x] Operations: worker Docker target/Compose profile, complete env examples and deployment docs including Vercel limits, Stripe forwarding and manual 4242 test instructions. No configured Stripe credentials exist in this workspace; never claim a real hosted test purchase without them.
- [ ] Verify: root/bridge pytest, lint, production build, both Docker targets and worker Compose configuration/build; secrets audit; final review; commit and normal push main; inspect CI.
